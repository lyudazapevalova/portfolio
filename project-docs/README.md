Обновлено: 14 октября 2026, Asia/Almaty.

Эта папка хранит контекст проекта для работы в разных чатах. Сначала прочитайте этот файл, затем основной план. История предыдущего чата не нужна для продолжения.

## Задача

Создать личный сайт-портфолио продуктового дизайнера. Сайт должен показывать качество интерфейсов, объяснять личный вклад и помогать быстро познакомиться с дизайнером. Главная работа — коммерческий опыт в Zimran над Finelo. Остальные проекты преимущественно учебные: их статус обозначаем честно и спокойно.

Люда одобрила переход к первому макету: **сначала главная и Finelo, затем остальные кейсы по одному**. Первый интерактивный макет v0.1 собран в [portfolio-prototype](../site/README.md).

## Ключевые решения пользователя

- Светлый минималистичный сайт с крупными изображениями и уместным движением. Палитра — приятные приглушённые пастельные цвета умеренной яркости; без тёмных фонов и крупных тёмных блоков. Это прямое уточнение Люды, а не предложение ассистента.
- Полные русская и английская версии, переключатель EN / RU.
- Простой язык в духе «Пиши, сокращай»: конкретно, понятно, без канцелярита.
- Порядок основных проектов: **Finelo → Иви → Ozon → Звук**. Веб-работы в конце: CinemaPark и сервис планирования питания Plate Planner.
- Finelo начинается с нескольких серий UI и коротких пояснений: путь обучения, уроки, игровые механики, дополнительные инструменты. Затем направления личной работы с сериями экранов, и только после них подробные кейсы. Не сводить начало к одному ролику и подписи «Обзор приложения».
- В паспорте кейса нужны краткие сведения: продукт, роль, команда, сроки, тип проекта и подходящие теги.
- Никаких выдуманных результатов, процентов или коммерческих заказов.
- В публичной истории web-to-app не упоминать ранний отток после создания аккаунта и email-кампанию.
- Чат с CX-агентом внедрили после эксперимента с доступом к поддержке. Аналитики по чату нет; публично пишем только о внедрении, без оговорки об отсутствии данных. Не переносим на него чужие результаты.
- Апселлы: показываем итоговые экраны, учёт требований комплаенса и сохранение ARPU. Без акцента на варианте C и плашке. Перенос апселлов после онбординга исключён: тест не раскатили.
- Исследование: первоначально поиск каналов маркетинга; два итога — выводы для маркетинга и пользовательские проблемы с гипотезами. Пример внедрённых подсказок для купленных функций пока кандидат: Люда позже пришлёт скриншоты, затем решим, включать ли его.
- В составе команды CEO первым или последним; текущий текст — CEO первым, Rive-аниматор рядом с дизайнерами.
- Основной визуальный материал — реальные макеты. Пользователю не нужно готовить новые презентации.

## Как поддерживать документы

- Новые решения по сайту вносить в PROJECT_PLAN.md; факты о Finelo — в FINELO_BRIEF.md; ссылки — в SOURCES.md.
- В конце содержательного этапа обновлять дату и таблицу статуса в этом файле.
- Если пользователь меняет решение, обновлять действующую формулировку, а прежнюю кратко отмечать в журнале изменений основного плана. Не оставлять два противоположных указания как действующие.
- Указывать источник результата: слова Люды, старое портфолио, резюме, просмотренные макеты или аналитика. Макет сам по себе не доказывает запуск и рост показателей.
- Новые версии текстов и дизайна сохранять в этой проектной папке или связанных папках результатов; не оставлять единственный экземпляр в сообщении чата.
- Если новому чату недоступен локальный путь или Figma, сообщить о конкретном ограничении и продолжить по доступным материалам. Не утверждать, что источник просмотрен, если этого не было.
